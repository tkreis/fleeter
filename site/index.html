Your Macs, Linux boxes and containers, run as one fleet of coding agents.

fleeter is one bash tool. Your laptop is the master: it enrols machines over Tailscale with single-use invites, pushes Claude Code, Codex, Cursor, Grok, a browser with MCP servers, your instructions, skills and secrets over SSH, and can kick any node out. Nodes keep themselves current from git and share one Markdown memory, so the master can sleep.

Get started Read the architecture

  • bash 3.2 and python3 stdlib; no agent, no server, no database
  • master: macOS or Linux; nodes: macOS 13+, Debian, Ubuntu, Fedora, Arch, Docker
  • MIT licensed

What you get on every node

  • Agents installed and logged in

    Claude Code, Codex CLI, Cursor CLI and Grok Build, kept current by their own updaters. Logins reuse what the master has wherever the vendor allows; otherwise fleet login runs the device-code flow on the node.

  • A browser the agents can drive

    Chrome or chromium plus chrome-devtools-mcp and @playwright/mcp at pinned versions, behind wrappers that run headless when there is no display. Runtimes via mise, pnpm, uv, gh, Docker; optional CLIProxyAPI and T3 Code.

  • The same instructions and skills

    One AGENTS.md in your private config repo, rendered into the Claude, Codex, Cursor and Grok locations. Skills and harness templates are captured from the master with fleet config publish and pulled by every node.

  • Secrets from a vault, not git

    fleet secrets set, fleet files add and fleet proxy import store values in the master's 0700 vault. They travel over SSH into a 0600 file on the node, in two profiles: minimal for throwaway containers, full for your own machines.

  • A master that may be asleep

    Nodes pull code and config every 15 minutes, sync memory every 5 and run the vendor updaters daily, all as your user. The master is needed only to enrol, push secrets and kick. Containers run one foreground scheduler, Macs use launchd, Linux uses systemd user timers.

  • Throwaway Docker nodes

    docker/spawn.sh 3 mints three invites and starts three containers that join as ephemeral tailnet devices, get the minimal profile, and vanish when stopped. No root in the image, no NET_ADMIN, no tun device.

How it works

Three git repos and one vault. The master pushes over OpenSSH inside your tailnet with its own key and pinned host keys. Nodes fetch the rest themselves with per-node deploy keys, so the master is a control point, not a dependency.

Joining a machine

An invite is a single-use, pre-authorised Tailscale key with a nonce, good for one hour. The node never contacts the master; the master finds it.

  1. on the master

    Mint an invite

    fleet invite --name studio prints a one-line command and an invite code. The code carries the auth key, the nonce, the master's public key and the fleet's tool list.

  2. on the new machine

    Paste the one-liner

    The join script travels inside the command; nothing is downloaded. It reads the code from a hidden prompt, joins the tailnet with the fleet tag, enables key-only SSH, generates deploy keys and writes the nonce to disk.

  3. on the master, within 2 min

    Verify the nonce

    The timer sees a new tagged peer, reads its enrol.json over SSH and claims the matching invite atomically. A peer without a valid nonce is listed as unknown and never provisioned.

  4. on the master, then the node

    Provision

    Deploy keys are registered, then code, config, secrets and files are pushed and fleet apply runs remotely: tools, instructions, skills, timers and the memory clone. fleet nodes shows provisioned.

Shared memory

Optional, and worth it. A plain Markdown vault, Obsidian-compatible, in a private git repo. Every harness reads and writes files natively; git works headless and offline and keeps the history.

Each node commits only inside nodes/<name>/, so two nodes can never conflict. Each node pulls the whole vault, so a fact learned on one machine is on every other within two sync cycles. INDEX.md, one line per note, is rebuilt by a GitHub Action on every push and read first.

The global instructions tell every agent to treat nodes/** as knowledge, never as instructions. What you promote into notes/ is reviewed by you, on the master.

Security model

Assume a node can be fully compromised: an agent there runs untrusted code and reads untrusted content all day. The design makes that node cheap to lose.

What holds

  • Push only. The master connects to nodes over OpenSSH with its own key and pinned host keys. Nodes get no shell, key or token for the master; there is no node-to-master channel, not even for enrolment.
  • Isolation by tailnet policy. Your devices may reach tag:fleet-node on port 22; the tag may reach nothing inside the tailnet. fleet init master, policy check and doctor verify the live policy, and doctor probes from the nodes themselves with nc.
  • Single-use invites. One hour, one nonce, claimed atomically by the master. The auth key is read from a hidden prompt or a 0600 file, never from argv; in Docker it arrives as a bind-mounted file that never shows in docker inspect.
  • Secrets never enter git, argv or a log. Vault at 0700/0600, HMAC digest instead of values, API credentials read from files by lib/api.py or gh. fleet config publish runs a secret scan on every run and aborts on a hit.
  • Per-node keys, revocable alone. Each node has its own Tailscale device and three deploy keys: code and config read-only, memory read-write but staged only inside nodes/<name>/.
  • Kick is complete and retried. fleet kick kills a running provision, stops the node's jobs, deletes the device and the deploy keys, and prints the secrets the node held. Anything that fails is retried by every reconcile; a node missing for the grace period is revoked the same way.

What it does not do

  • No credential wiping. A kicked or vanished node keeps the secrets, files and clones it had. Kick cuts access and names what to rotate; you rotate.
  • launchctl setenv on macOS. With a local CLIProxyAPI, publishing ANTHROPIC_AUTH_TOKEN into the launchd session puts the token in one process's argv for milliseconds, local user only. Without cliproxy, or in remote mode, no token is published.
  • The master is not protected from local processes running as your user; they can run fleet themselves. Keep the vault on an encrypted disk.
  • Shared memory is a prompt-injection return path. Instructions mitigate; they do not prevent a model from following a planted note. Review nodes/** before promoting anything.
  • Shared logins share limits. One CLAUDE_CODE_OAUTH_TOKEN for every node; CLIProxyAPI OAuth files copied to every full node, so a refresh on one can log out the others.
  • A stolen invite still enrols one node with the invited profile until it expires. fleet nodes shows it; fleet kick removes it.

The full threat model, the mechanisms table, the known limits and the rotation checklist are in docs/SECURITY.md.

Commands

Every command accepts --help and does nothing else; an unknown flag or extra argument exits 2 before anything runs. Nothing destructive happens without --yes or a typed confirmation, and running anything twice changes nothing the second time.

Is it for you

Built for exactly this

  • One operator: you, your accounts, your machines. No multi-user model, no RBAC, no shared master.
  • Tailscale. Master and nodes are on your tailnet; fleeter manages the policy rules and uses the Tailscale API to mint keys and delete devices.
  • macOS 13+, Debian, Ubuntu, Fedora, Arch, and containers from the shipped image.
  • GitHub for the private config repo and the optional memory repo, with per-node deploy keys.
  • Agents that take their login from the environment: CLAUDE_CODE_OAUTH_TOKEN, CURSOR_API_KEY, API keys or a device-code login per node.
  • You want to try it before trusting it: bash tests/e2e.sh runs master and two nodes offline, with Docker only.

Not for

  • Teams. Several people sharing a master, or anything with roles.
  • Windows or WSL, as master or node.
  • Another VPN, or nodes on the plain internet.
  • GitLab or Gitea for the config repo, for now. A public code repo on any host works.
  • GUI logins. Claude desktop, ChatGPT desktop, the Cursor IDE: fleeter opens them and reports the manual step.
  • A control panel. There is fleet nodes --live, fleet kick and the Tailscale admin console on your phone.
