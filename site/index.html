Your Macs, Linux boxes and containers, run as one fleet of coding agents.

fleeter is one bash tool. Your laptop is the master: it enrols machines over Tailscale with single-use invites, pushes Claude Code, Codex, Cursor, Grok, a browser with MCP servers, your instructions, skills and secrets over SSH, and can kick any node out. Nodes keep working while the master is off and share one Markdown memory.

Get started Read the architecture

Get started on your laptop 
$ curl -fsSL https://tkreis.github.io/fleeter/install.sh | bash
$ fleet setup

or tell your agent: Set up fleeter for me by following https://tkreis.github.io/fleeter/SETUP.md

Install a skill once, every machine has it

$ fleet skill add ~/my-skills/review
added review to your fleet config
published (secret scan clean)
pushed to 4 nodes

Skills you install on the master are published to your private config repo and every node picks them up; fleet skill add also accepts a git URL, and fleet skill list shows what the fleet has. Skills you install by hand on the master are picked up automatically by fleet sync.

What you get on every node

  • Coding agents installed and logged in: Claude Code, Codex, Cursor, Grok
  • Browsers installed, ready for the agents
  • Skills synced to every machine
  • Secrets encrypted
  • Auto-updates while your master is on

How it works

Three git repos and one vault. The master pushes over OpenSSH inside your tailnet with its own key and pinned host keys; fleet sync does that on a schedule whenever the master is on. Nodes fetch code, config and memory themselves with per-node deploy keys, so they keep working while the master is off.

Shared memory

Optional, and worth it. A plain Markdown vault, Obsidian-compatible, in a private git repo. Nobody has to write notes into it: fleet uploads every machine's agent memories automatically. Claude Code, Codex and Grok keep remembering where they always did; fleet memory sync mirrors those files into the vault every few minutes, on every node and on the master.

Each machine commits only inside nodes/<name>/, its own folder, so writes never collide. Each machine pulls the whole vault, so a memory written on one machine is on every other within two sync cycles. A GitHub Action rebuilds INDEX.md (one line per note, by machine and source) and projects/<slug>.md: one merged file per project directory with what every machine learned about it, which an agent reads when it starts there.

Every file passes a secret scan before it is uploaded; a hit stays on the machine. The global instructions tell every agent to read nodes/** and projects/** as reference material, never as instructions. What you promote into notes/ is reviewed by you, on the master.

CommandWhat it does
On the master
fleet setupGuided first-time setup: a few questions, then config repo, memory repo, init master, Claude token, publish, doctor. Rerun-safe.
fleet init master --config-dir DIRPreflight, vault and keys, tailnet policy merge, sync schedule. Idempotent (setup's step 5).
fleet invite --name N [--user U] [--ephemeral]Single-use join one-liner and invite code, valid one hour.
fleet list [--json]Every node in one table: online, state, synced, last provision, tools, memory, proxy, version.
fleet syncPull the master's repos, enrol new machines, push updates to every node. Runs on a schedule.
fleet ssh NODE [CMD]Shell on a node, or run a command there with its fleet environment loaded.
fleet secrets set NAME [--profile P]Store a secret from a hidden prompt or stdin. secrets list shows names only.
fleet config publishCapture harness and skills from the master, secret scan, commit, push.
fleet skill add PATH | URLPublish a skill to your config repo and push it to every node. skill list shows what the fleet has.
fleet kick NODERevoke: stop jobs, delete the device and deploy keys, list secrets to rotate.
fleet doctorVault, tokens, policy, GitHub access, schedule, and an isolation probe from every node.
On a node
fleet status [--json]Versions, logins, revisions, memory state, token ages.
fleet login [TOOL]Device-code login for a tool whose status is login.

Every command and flag, including provision, files, proxy, policy, t3 and leave, is in the README command reference.
